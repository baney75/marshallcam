## 2. THE BUG to fix properly (top priority)
Today, on the kiosk Mac at boot the Web App launches ~11 s before the server is listening. The client (`client/src/App.tsx`, `App()` near the bottom) calls `/status?token=...`; the fetch fails, and the `.catch` calls `clearStoredToken()`; also any non-ok response clears it. Worse, server sessions live in an in-memory `Map` with a 24 h TTL, so ANY server restart invalidates every token, and the station falls back to the PIN pad, which needs a human. The guard script works around it by typing the PIN via AppleScript. Fix it for real:
1. Server: replace in-memory sessions with **stateless signed tokens**: `base64url(payload).base64url(HMAC-SHA256(SESSION_SECRET, payload))`, payload `{v:1, kind:'user'|'station'|'admin', iat, exp, jti}`. Verify with `crypto.timingSafeEqual`. Tokens survive server restarts. Logout adds `jti` to a small revocation list persisted in `DATA_DIR/revoked.json` (prune expired). Put this in `src/auth.ts` with no side effects at import time so it is unit-testable. Keep cookie names and query param names compatible (`marshall_token`, `token`, `max_token`).
2. Server: keep the existing `isLocalStation(req)` loopback trust rule (loopback remote address, Host localhost/127.0.0.1, NO proxy headers like x-forwarded-for/cf-connecting-ip/cf-ray/x-real-ip/forwarded) and add `POST /station/session`: only for local-station requests, returns `{ok:true, token}` for a long-lived `station` token (STATION_TOKEN_TTL_DAYS). Non-local → 403. Make `/ws` and `/livekit-token` accept a valid signed token OR a local-station request.
3. Server: add `GET /healthz` (no auth, `{ok:true, uptime}`) for readiness, and `POST /station/heartbeat` (local station only) + `GET /station/health` (local only: `{stationConnected:boolean, lastHeartbeatAgeSec}`) so the guard can tell whether the TV is actually publishing.
4. Client: extract the auth bootstrap into a pure, testable module `client/src/authBootstrap.ts`: given role, stored token, and an injectable fetch, it (a) waits for `/healthz` with backoff (1 s → max 10 s, indefinitely for station, ~60 s for remote) showing a "Connecting to server…" state instead of the PIN pad; (b) validates the stored token; clears it ONLY on an explicit 401/403 response, never on network errors or 5xx (retry those); (c) if role is station and there is no valid token, call `POST /station/session` and store the result; (d) only show the PIN pad when all that fails (remote users, or a station reached over the network). The station view should send `/station/heartbeat` every 15 s while connected to LiveKit. If a LiveKit/token call later returns 401 for the station, re-provision via `/station/session` instead of logging out.
5. `detectRole()`: drop the hard-coded LAN IP; station when `?role=station`, or hostname is localhost/127.0.0.1; keep private-range heuristic only behind `?role=`.
6. Camera/mic permission: request getUserMedia once per page load and reuse the stream; never re-request on reconnects. Document in README how to set the Safari Web App's per-site Camera and Microphone to "Allow" once (Web App Settings → Websites), and keep the auto-approve helper as a fallback.
